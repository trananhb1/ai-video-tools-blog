## LCP Fix — Technical Detail

**Root cause (assessed):** Both top-2 traffic pages had:
```html
<link rel="preload" href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap" as="style">
<link rel="preconnect" href="https://fonts.googleapis.com">   <!-- after preload: wrong order -->
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap" rel="stylesheet">
```

The preload for an external stylesheet (not a font file directly) causes:
1. Browser fetches the CSS early
2. The regular `<link rel="stylesheet">` then triggers a second fetch for the same URL
3. The font files referenced inside the CSS need another round trip to gstatic.com

**Fix applied:**
```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap" rel="stylesheet">
```

Preconnect before the stylesheet link ensures the TCP handshake is done before the stylesheet request fires. The `display=swap` parameter in the URL (Google's addition) ensures text remains visible during font load, so the LCP element (h1 text) isn't blocked.

**Expected improvement:** LCP should drop significantly — the double-fetch was the most likely cause of the 332% spike. If LCP remains high after this cycle, the next suspect is AdSense injecting above-the-fold ad images.
